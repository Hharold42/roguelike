# Roguelike

Top-down roguelike-survivor на [Babylon.js](https://www.babylonjs.com/) + TypeScript + Vite.
Бесконечная процедурная карта, волны врагов, улучшения между этапами.

## Запуск

Нужен [Node.js](https://nodejs.org/) 20+ (проверялось на 24).

```bash
npm install      # один раз, ставит зависимости
npm run dev      # dev-сервер с горячей перезагрузкой
```

Откройте адрес из консоли (обычно http://localhost:5173). Изменения в `src/` подхватываются без перезапуска.

Продакшен-сборка:

```bash
npm run build    # проверка типов + сборка в dist/
npm run preview  # локально посмотреть собранную версию
```

Содержимое `dist/` — статика, её можно выложить на любой хостинг.

## Управление

На старте — выбор оружия: **пистолет** (дальний бой, ствол греется) или **меч** (взмах по сектору перед собой, урон ×3). Камера от третьего лица, как в Genshin Impact: первый клик по полю захватывает курсор.

| Действие | Клавиши |
|---|---|
| Движение (относительно камеры) | `W A S D` / стрелки |
| Прыжок | `Пробел` |
| Присед (удерживать) | `Ctrl` / `C` |
| Камера | мышь (с захваченным курсором) |
| Дистанция камеры | колесо мыши |
| Атака (выстрел / взмах) по перекрестию | зажать ЛКМ |
| Колесо фортуны (оружие и предметы за золото) | `B` (в колесе: `Пробел`/`Enter` — крутить, `Esc` — закрыть) |
| Отпустить курсор | `Esc` |
| Новый забег после смерти | `R` |

Оружие всегда наготове: корпус повёрнут на точку под перекрестием, рука с пистолетом наклоняется за ней вверх/вниз; движение вбок и назад — стрейф (назад ноги идут в обратную сторону). Камера не проваливается в склоны и подтягивается ближе, если между ней и персонажем стена. Параметры (чувствительность, пределы наклона и дистанции) — в `src/thirdPersonCamera.ts`.

Движение с инерцией: разгон до полной скорости ≈ 0.15 с, остановка ≈ 0.15 с; упёрлись в стену — скорость гаснет. Прыжок (`src/player.ts`):

- **переменная высота** — удерживать пробел ≈ 2.2 юнита, отпустить сразу ≈ 0.6;
- гравитация асимметричная (взлёт мягче, падение резче) с коротким «зависанием» в вершине;
- в воздухе инерция сохраняется: прыжок с разбега — leap на несколько юнитов, подруливание слабое, отпустили клавиши — скорость плавно гаснет;
- **coyote time** 0.1 с после схода с края и **буфер** 0.12 с до приземления — нажатие не теряется;
- приземление амортизируется (колени, наклон) и при жёстком падении режет разбег;
- камера по вертикали следует за персонажем с запаздыванием, чтобы прыжки не дёргали кадр.

Присед вдвое замедляет; модель садится по-настоящему — сгибом бёдер и коленей с опусканием таза (стопы остаются на земле), корпус наклоняется вперёд, коллайдер и точка обзора камеры опускаются. Прыжок из приседа выпрямляет.

Стены физические: сбоку блок не пройти, но на него можно запрыгнуть и ходить по верху (`Terrain.floorAt` — верх стены или рельеф под персонажем). Никакого «примагничивания»: чтобы оказаться на блоке, ступни в прыжке должны подняться выше его верха (прыжок ≈ 2.2, низкие блоки 1.8–2.2 берутся с земли), высокие — ступеньками с соседних блоков. Сошёл с края — падаешь. Враги по стенам не лазят и **не достают игрока на блоке**: удар проходит, только если ступни игрока не выше ступней врага на `ATTACK_HEIGHT` (1.1). Толпа собирается у подножия (flow field стартует от свободных клеток вокруг блока).

## Враги

- Модель — та же, что у игрока (`/models/player.glb`), **в 3/4 роста** (`ENEMY_SCALE`) и перекрашенная: обычные — красные, к 9-му этапу — фиолетовые; элитные — в 1.35 раза крупнее (≈ рост игрока), тёмно-красные, светятся. Нет файла — процедурный человечек. Каждый враг — независимая копия шаблона со своим скелетом и ригом (`loadCharacterTemplate` → `instantiate`), меши склеены в один (`mergeSkinned`): один draw call на врага.
- **Толпа, а не колонна**: у каждого свой боковой снос вдоль маршрута (постоянный + качающийся), скорость ±20 %, а ближе 9 юнитов враг идёт не по прямой, а со своего угла — вместе с расталкиванием получается кольцо вокруг игрока. Проверка на 40 врагах из узкого сектора: через 9 с заняты все 8 секторов вокруг игрока.
- **Удар с замахом**: 0.32 с от начала выпада до урона, урон проходит только если в этот момент игрок всё ещё в зоне — отбежать или отпрыгнуть можно. Модель делает выпад вперёд.
- **Реакция на урон**: вспышка красным на 0.18 с — самосвечение материала уходит к насыщенному красному, базовый цвет гасится (иначе выходил розово-белый), плюс ореол через GlowLayer (`metadata.glow`). Материалы у каждого врага свои, но объект цвета после перекраски был общим (`stats.tint`), а сеттеры Babylon игнорируют присваивание равного цвета — `ownColor` в `enemy.ts` даёт каждому собственный. **Пуля** (ручной или летающий пистолет) ещё и **замедляет** до 60 % скорости на 0.7 с (`BULLET_SLOW*` в `projectiles.ts`, `Enemy.applySlow`); меч и автоматика не замедляют.
- **Купон колеса** падает с врага с шансом 3 % (элита и боссы — 20 %, `COUPON_CHANCE*` в `game.ts`): зелёный билет с той же физикой, что монеты, не исчезает со временем; подбор даёт бесплатное вращение.
- Статы (`game.ts`): HP 3 + 1.5/этап (элита ×6), скорость 4.2 + 0.3/этап, урон 8 + 2/этап. Толпа в начале этапа 10 + 4/этап, штурм ×4.
- **Золото** (`gold.ts`): с врага падает 2 + этап/2 (элита 12 + 2·этап) монетами (до 5 штук), они подпрыгивают, ложатся на землю и в радиусе 4.5 юнита летят к игроку. Лежат монеты 25 с. Шкала в HUD ведёт к цене следующего вращения колеса фортуны. Предмет «Жадность» добавляет золота с каждого врага, «Магнит» — увеличивает радиус притяжения (`GoldPool.magnetDist`).

## Оружие (`weapon.ts`)

Любое оружие — наследник абстрактного `Weapon` (свой базовый кулдаун, метод `tryFire(origin, target)`). Характеристики у всех оружий **общие** — `WeaponStats` в `player.weaponStats` (урон, «снарядов» за атаку, множитель кулдауна). Улучшения между этапами меняют именно этот объект, а не конкретный экземпляр, поэтому «Тяжёлые снаряды», «Мультивыстрел» и «Скорострельность» действуют на всё сразу — и на стартовое оружие, и на летающий пистолет, купленный позже.

- **`Gun`** — огнестрел: стреляет через общий пул пуль (`ProjectilePool` только двигает пули и считает попадания), греется при непрерывной стрельбе. Экземпляры: пистолет в руке (кулдаун 0.22) и летающий пистолет (0.5, без нагрева).
- **`Sword`** — меч: удар — серия из `projectiles` взмахов (чередуются слева/справа), каждый бьёт **всех** врагов в секторе 130° радиусом 2.6, если их ступни не выше/ниже на 1.6. Первый взмах — у игрока, а каждый следующий — **волной**: на `SWING_STEP` (1.6) дальше по направлению удара от точки, где игрок стоял в момент удара (снимок, не ссылка — можно развернуться и убежать, волна доходит). Серии независимы: новый удар ограничен только кулдауном и может начаться, пока волна предыдущего ещё идёт. Урон взмаха = `damage × 3`; взмахи ускоряются вместе с кулдауном. Попадания идут через тот же хук, что у пуль, — молния срабатывает и от меча. Анимация: оружейная рука уходит вбок (`CharacterModel.swing`, у GLB — yaw плечевой кости), рука показывает самую свежую серию; на земле подсвечивается сектор каждого взмаха (пул дисков, гаснут независимо).

Стартовый выбор — экран `#weaponOverlay`, список `START_WEAPONS` в `game.ts`. Что вложено в руку модели, задаёт `HeldWeapon` (`"gun" | "sword" | "none"`) — пистолет берётся из `public/models/gun.glb` (см. ниже; нет файла — примитивы `buildGunMesh`), меч — из примитивов (`buildSwordMesh`); на кисть садятся одинаково: ствол/клинок вдоль предплечья.

## Колесо фортуны (`wheel.ts`, `weapons.ts`, `shopItems.ts`)

Азартный вход в экран **B** (первая вкладка; рядом — магазин и крафт, см. ниже). Открыть можно всегда, крутить — если хватает золота. Первое вращение стоит 50, каждое следующее на 50 дороже (`SPIN_BASE`, `SPIN_STEP` в `game.ts`; «Скупка» снижает шаг до 30) — цена не сбрасывается между этапами. На колесе лежат все **ещё не выигранные оружия** и **предметы колеса**; **каждый второй сектор пустой** — проигрыш. Размер сектора приза пропорционален его весу (`weight`), пустой сектор за ним — такого же размера, а остановка — равномерный случайный угол, поэтому колесо честное: шанс приза = его доля среди призов × 50 %, что и написано в легенде справа. Выигранное оружие уходит с колеса, предметы остаются (их можно выиграть повторно — бафы складываются). Отрисовка — canvas 2D (`FortuneWheel`), остановка с ease-out за 4.2 с, не меньше 5 оборотов; `spin(angle, 0)` — мгновенно, для тестов.

### Утешительное колесо

Пустой сектор — не совсем проигрыш: поверх основного открывается второе колесо (`#bonusOverlay`, тот же `FortuneWheel` с `empties: false, autoSpin: true`), которое **само крутится один раз бесплатно** через 0.45 с. На нём все обычные улучшения из `UPGRADE_POOL` поровну (те же, что выбираются между этапами) и красный сектор **«10 боссов»** с шансом ровно 2 % (`BOSS_CHANCE`; вес подобран под долю). Боссы — элитные враги с множителем размера `scale: 2.2` (`EnemyStats.scale`, ≈ 4.5 юнита ростом), HP ×25 и урон ×3 от обычного врага этапа, золото 40 + 5·этап; идут в очередь спавна мимо лимита живых. Свечение у них приглушено пропорционально размеру (`metadata.glowMult`), иначе bloom заливал бы их в белый столб. `Esc`/«Забрать» закрывает верхнее колесо и возвращает к основному — можно крутить дальше. Клавиши слушает только верхнее колесо (`FortuneWheel.stack`).

### Оружия (`WEAPONS`, вес в скобках)

Все берут урон из общих `weaponStats`, но мультивыстрел и скорострельность трактуют по-своему:

- **Летающий пистолет** (10). Парит слева над плечом, сам разворачивается на ближайшего врага в радиусе 28 и стреляет 2 раза в секунду (быстрее с бафами скорострельности, веером при мультивыстреле). Ствол не греется. Пули те же, что у игрока.
- **Бумеранг** (8, `autoWeapons.ts`). Раз в 1.4 с летит к ближайшему врагу в 16 юнитах (на 4–12 юнитов), пробивая всех по пути, разворачивается и возвращается к игроку — каждого врага бьёт по разу туда и по разу обратно, урон ×2 за касание. Мультивыстрел — несколько бумерангов веером по 22°. Летит на высоте 1 над опорой.
- **Орбитальные клинки** (8). Два клинка кружат вокруг игрока на радиусе 2.4 и режут всех, кого задевают: урон ×1.5, один враг — не чаще раза в 0.45 с. Мультивыстрел добавляет по клинку, скорострельность крутит быстрее (2.6 рад/с ÷ `cooldownMult`).
- **Мортира** (7). Раз в 2.4 с навесом кидает снаряд в самое **плотное** скопление врагов в 3–22 юнитах (цель — враг с наибольшим числом соседей в 3 юнитах); через 0.9 с взрыв радиусом 3.2 с уроном ×4. Мультивыстрел — по снаряду на каждое следующее скопление вне радиуса уже выбранных взрывов. Ближе 3 юнитов не стреляет, чтобы не накрыть себя.
- **Молния** (5). Любое попадание любого оружия (пуля, взмах, бумеранг, клинок, взрыв) с шансом 30 % бьёт ещё по двум ближайшим врагам в 8 юнитах от поражённого, урон — как у попадания. Молния молнию не запускает.
- **Radiance** (3). Кольцо радиусом 6: враги внутри каждые 0.5 с получают половину урона игрока (минимум 1), а их удары с шансом 30 % наносят 10 % урона (`WeaponSystem.incomingDamage`).

### Предметы (`SHOP_ITEMS`)

Предметы колеса (у них `weight > 0`): Аптечка (+50 HP), Сердце (+20 макс. HP), Мешок золота (+100, только на колесе), Сапоги (+10 % скорости), Щит (поглощает 3 следующих удара целиком — `player.shield`, видно в HUD), Магнит (радиус притяжения монет ×1.5), Жадность (+1 золото с врага), Адреналин (кулдауны всех оружий ×0.7 на 20 с — временный баф, `Game.timedBuffs`), Бомба (убивает всех в радиусе 12, золото выпадает), Купон (только на колесе: бесплатное вращение или −50 % на покупку). Предметы работают через `ItemHost` — узкий интерфейс того, что им можно трогать в игре: игрок, `Perks`, оружие в руке, `killAround`, `slowAround`, `timedBuff`, `freeSpin`, `magnet`.

Предметы **только магазина** (`weight: 0`, цена в скобках). Уникальные (`once`) исчезают из ассортимента, пока `owned(host)`:

- Оружейные: **Крит** (250, +10 % шанс крита — урон ×3, `WeaponStats.critChance`, действует на все оружия, включая автоматику через `dealDamage`), **Пробитие** (250, пистолет: пуля проходит ещё одного врага, урон ×0.5 за пробитие), **Рикошет** (200, пистолет: пуля от стены/земли летит в ближайшего врага в 10 юнитах, один раз), **Ярость** (250: убийство −3 % к кулдаунам на 5 с, до 10 стаков — `WeaponStats.tempCooldownMult`), **Тяжёлый клинок** (300, меч: сектор 180°, урон ×1.33, кулдаун ×1.3 — `Sword.applyMods`), **Охлаждение** (200, пистолет: убийство обнуляет нагрев на 3 с — `Gun.suppressHeat`).
- Живучесть: **Второе дыхание** (400, один раз вместо смерти — 50 % HP и щит на удар), **Шипы** (250, 30 % полученного урона возвращается ударившему), **Каменная кожа** (300, −15 % входящего урона, складывается), **Вампиризм** (200, +1 HP за убийство), **Адреналиновая аптечка** (100, +30 HP и скорость ×1.2 на 10 с).
- Экономика и колесо: **Счастливая монета** (150, пустые секторы 50 % → 40 % до первого «пусто» — `FortuneWheel.emptyShare`), **Весы** (150, веса оружий ×1.5 на одно вращение), **Скупка** (200, цена вращения растёт на 30 вместо 50), **Кошелёк** (300, золото с врага ×1.25), **Пробирка** (150, следующее утешительное колесо: боссы 10 %, но их золото ×3), **Заморозка** (100, расходник: враги в радиусе 15 замедляются до 30 % на 4 с).

Постоянные перки лежат в `Perks` (`shopItems.ts`), их читает `Game` (`tickPerks`, `onEnemyKilled`, цикл урона врагов, `die`). Предметы с `undo` (Щит, Магнит, Жадность, Каменная кожа) считаются в инвентаре `Game.itemCounts` — они ингредиенты крафта.

## Магазин и крафт (`shop.ts`, `recipes.ts`)

Экран **B** — три вкладки (клавиши `1`/`2`/`3`): **Колесо фортуны**, **Магазин**, **Крафт**. Игра на паузе; пробел крутит колесо только на его вкладке (`FortuneWheel.keysEnabled`).

**Магазин** — гарантированная, но дорогая альтернатива колесу. Ассортимент обновляется каждый этап (`Game.rollStock` в `beginStage`): 3 случайных доступных предмета (`purchasableItems`) + 1 невыигранное оружие по цене из `WeaponDef.price` (дрон 400, бумеранг 350, клинки 350, мортира 450, молния 600, Radiance 900). Купленное исчезает из ассортимента и с колеса. Кнопка «Использовать купон» — одна покупка за полцены (тратит купон). Справа — своя автоматика с кнопкой **Продать** за половину цены (`WeaponSystem.revoke` убирает меши; оружие возвращается на колесо).

**Крафт** — рецепты как данные (`RECIPES`): ингредиенты + золото → результат. Ингредиенты **тратятся**: баф откатывается (`UpgradeDef.undo`), предмет откатывается (`ShopItem.undo`), оружие забирается (кроме `keep` — когда результат улучшает его же). Рецепт виден, если подходит стартовому оружию (`onlyWeapon`) и ещё не сделан (`done`); карточка показывает ✓/✕ по каждому ингредиенту. Инвентарь бафов — `Game.upgradeCounts` (`applyUpgrade` считает карточки этапов и утешительное колесо).

| Рецепт | Ингредиенты | Результат |
|---|---|---|
| Вампирские пули | пистолет, Регенерация, 2500 | 8 % урона пуль лечит (`bulletLifesteal`, работает и у дрона) |
| Дробовик | пистолет, Мультивыстрел ×2, 1500 | `GUN_PRESETS.shotgun`: +5 пуль конусом 25°, дальность 12, урон ×0.6, кулдаун ×2 |
| Автомат | пистолет, Скорострельность ×2, 1500 | `GUN_PRESETS.rifle`: кулдаун ×0.35, нагрев ×2, разброс до 5°. Исключает Дробовик |
| Гранатомёт | пистолет, Мортира, 3000 | пуля взрывается радиусом 2 (`bulletBlast`, урон взрыва ×0.5 — `Game.bulletBlast`) |
| Рывок-удар | меч, Лёгкие ноги, 1500 | перед ударом рывок на 3 вперёд (`Sword.dash` → `Game.dashPlayer`, стены останавливают) |

### Сводка справа сверху (`#statsHud`)

`Game.updateStatsHud` собирает каждый кадр (DOM трогает только при изменении строки): оружие в руке (название пресета/модификации) с уроном, числом снарядов/взмахов, скоростью атаки (с учётом ярости), сектором меча и нагревом ствола; перки оружия (крит, пробитие, рикошет, взрыв, вампиризм пуль, молния, рывок, охлаждение, стаки ярости); автоматика; макс. HP, скорость, реген, броня, шипы, вампиризм, второе дыхание; предметы (щит/аегис, бонус и множитель золота, магнит, купоны); модификаторы колеса; временные бафы с оставшимися секундами.

## Графика

`src/environment.ts` — всё окружение в одном месте:

- **небо** — процедурный `SkyMaterial` из `@babylonjs/materials`: солнце на небе стоит там, откуда светит `lightDir`, так что тени и блики согласованы с диском солнца. Мутность, голубизна, яркость — константы `SKY_*`;
- **свет** — тёплое солнце (`DirectionalLight`) плюс полусферический свет неба: голубоватый сверху, тёплый отражённый снизу;
- **тени** — PCF с `normalBias` (размытые экспоненциальные давали сплошное самозатенение на призмах стен), ортокадр 90×90 юнитов вокруг игрока, чтобы разрешение карты теней не размазывалось по всем загруженным чанкам. Стены — flat shading (`convertToFlatShadedMesh`), иначе шестигранник затеняется как цилиндр;
- **дымка** — экспоненциальный туман в цвет горизонта; плотность подобрана так, чтобы край загруженных чанков (~70 юнитов) тонул в ней;
- **постобработка** — `DefaultRenderingPipeline`: FXAA, bloom только на ярких эмиссивах (трассеры, ствол, элитные враги), тонмаппинг ACES, лёгкая виньетка. Если нужна производительность — отключите вызов `setupPostFx` в `game.ts` или уберите bloom.

### Стрельба

Пуля — маленький быстрый трассер (260 юнитов/с, дальность 120). Вылетает из среза ствола и летит по прямой в точку, которая была под перекрестием в момент выстрела (враг, земля или, если там небо, далёкая точка по направлению камеры). Столкновения проверяются по всему отрезку пути за кадр, поэтому пуля не проскакивает врагов и стены на любом FPS.

Разброс: с некоторым шансом пуля отклоняется на 1–2° в случайную сторону. Шанс — 2 % у «холодного» ствола и растёт с каждым выстрелом подряд до 30 % (примерно 12 выстрелов). После окончания очереди шанс возвращается к 2 % за 0,5 с (после пары выстрелов) … 2 с (после максимального нагрева). Перекрестие расходится с нагревом ручного пистолета. Константы разброса — в начале `src/weapon.ts`, полёта пули — `src/projectiles.ts`.

## Правила

- Этап длится 30 секунд. По истечении игра ставится на паузу и предлагает одно из трёх улучшений; после выбора игра продолжается с того же места.
- Враги появляются постоянно за краем экрана; с каждым этапом новые враги сильнее и приходят чаще. В начале этапа приходит толпа.
- Каждый 10-й этап — штурм: толпа в 4 раза больше, каждый 10-й в ней элитный (крепче, крупнее, светится красным).
- Отставшие враги телепортируются ближе к игроку — от толпы не убежать.

## Своя модель персонажа

Положите файл в `public/models/player.glb` — игра подхватит его автоматически. Пока файл грузится, показывается процедурный персонаж из примитивов.

### Модель пистолета — `public/models/gun.glb`

`weaponModel.ts` загружает файл один раз на сцену (`loadGunTemplate`) и делает копии для руки и летающего пистолета. Нет файла — рисуется заглушка из примитивов. Ориентацию модель может иметь любую: по геометрии определяется ствол (длинная горизонтальная ось), рукоять (нижние `GRIP_FRACTION` = 45 % высоты — их центр показывает, где зад) и дуло (противоположный конец). Модель поворачивается стволом в +Z, масштабируется до `GUN_LENGTH` = 0.42 по стволу, а стык рукояти со стволом ставится в ноль — там кисть. Срез ствола (`muzzleLocal`) — дульный конец на высоте оси ствола; из него вылетают пули. Геометрия меряется на живой копии в сцене с применённым скиннингом (у моделей с костями, как у текущей Sketchfab-модели, bind-поза отличается от покоя). Лимит — 20 000 треугольников. Меч пока из примитивов (`buildSwordMesh`).

### Страница просмотра — `/viewer`

Отдельная страница (ссылка в правом нижнем углу игры или http://localhost:5173/viewer): модель загружается тем же кодом, что и в игре, но её можно рассмотреть.

- ЛКМ — вращать камеру, колесо — зум, ПКМ — сдвиг; стрелка на полу показывает, куда персонаж считается смотрящим;
- **Ходьба** (или зажать пробел) — анимация шага; **Присед** (или зажать `C`); **Прыжок** (или `J`) — мини-физика с теми же числами, что у игрока: видно leap с разбега, прыжок с места и приземление; **Вращать** — подставка крутится; **Скелет** — кости линиями; **Каркас** — wireframe;
- **Разворот** — подкрутить угол, чтобы понять, какой `yaw` нужен модели без скелета; **Оружие** — что вложить в руку (пистолет / меч / ничего);
- панель показывает треугольники, меши, кости, найденные анимации и результат распознавания рига;
- **Открыть GLB…** или перетащить файл в окно — посмотреть любую модель, не копируя её в `public/models`. Так удобно проверять модель перед тем, как сделать её игровой.

Что делает загрузчик (`src/characterModel.ts`):

- приводит рост к 2 юнитам, ставит ноги на землю, центрирует;
- **упрощает** меши до бюджета 6 000 треугольников (`triangleBudget`). Меши со скелетом не упрощаются — упрощение теряет веса костей;
- модели тяжелее 150 000 треугольников (`triangleHardLimit`) отклоняются с предупреждением в консоли браузера (F12), остаётся процедурный персонаж;
- анимации из файла: группы с именами `walk/run/move` и `idle/stand` переключаются при движении; иначе зацикливается первая настоящая анимация (группы из одного кадра — это поза, они игнорируются);
- **скелет без анимаций** (типично для моделей со Sketchfab, MMD, Mixamo без клипов): `src/humanoidRig.ts` распознаёт гуманоидный риг по геометрии — имена костей не важны, нужны только суффиксы стороны (`.L/.R`, `Left/Right`). Находятся бёдра, колени, плечи, локти и кисти, а по ним — таз (общий предок бёдер), грудь (общий предок плеч), позвоночник между ними и голова;
- **поза**: T-поза или A-поза не остаётся как есть — левая рука опускается вдоль тела, правая вытягивается вперёд, в кисть ставится пистолет-заглушка из примитивов (замените на модель оружия в `attachPlaceholderGun`, `src/characterModel.ts`);
- **анимация** идёт от состояния движения (`src/motion.ts`: скорость, стрейф, полёт, приземление, присед), а не от нажатых клавиш:
  - ходьба — ноги шагают со сгибом колена, левая рука машет противофазно со сгибом локтя, правая держит прицел и лишь покачивается, корпус наклоняется по скорости и покачивается в такт, кренится в сторону стрейфа;
  - покой — дыхание грудью, перенос веса, голова медленно оглядывается и держит горизонт при наклонах корпуса, чуть повторяет наклон прицела;
  - присед — бедро вперёд на θ, колено назад на 2θ, таз опускается на длину ноги × (1 − cos θ): стопы остаются на месте;
  - прыжок с места — ноги поджаты, к земле распрямляются; **leap** с разбега — ведущая нога вперёд, задняя назад, свободная рука вверх; приземление — амортизация коленями;
  - наклон корпуса компенсируется в оружейной руке, так что ствол не уезжает с прицела;
- **разворот**: если риг распознан, направление «вперёд» берётся по стопам — по костям носков, а если их нет, по вершинам меша ступни (она выступает вперёд от лодыжки). Модель сама поворачивается лицом по камере. Если скелета нет — используется параметр `yaw` (по умолчанию 180°; если персонаж смотрит спиной, поставьте `0`).

Что пишет консоль при загрузке: `[rig] бёдра N, колени N, руки N, позвоночник N, голова, оружейная рука найдена` и угол разворота. Если рук/ног 0 — риг нестандартный, останется поза покоя.

Большие файлы (десятки мегабайт) грузятся долго и раздувают `dist/` — перед использованием лучше сжать модель, например через [gltf-transform](https://gltf-transform.dev/) (`gltf-transform optimize in.glb out.glb`) или Blender (Decimate).

## Производительность

Что сделано, чтобы толпа держала 60 FPS, и что помнить при доработках:

- **Никакого `moveWithCollisions` у врагов.** Движок коллизий Babylon проверяет движущийся меш против *всех* коллайдеров сцены; при 150 врагах и ~220 стенах это съедало 30 мс на кадр. Враги ходят по hex-клеткам: `terrain.isWallAt(x, z)` — O(1), при упоре скользят вдоль стены (`Enemy.update`). Игрок остался на `moveWithCollisions` — один вызов в кадр, коллайдеры — только стены.
- **Расталкивание толпы** — `CrowdSeparator`: пространственная сетка с ячейкой 0.8, соседей ищем в 3×3 ячейках. Было O(N²) пар × коллайдеры, стало O(N). Игрок — твёрдый круг, врагов из него выталкивает.
- **Враги — скиннованные клоны одной модели**, поэтому толпа больше не бесплатна: один меш (склейка `mergeSkinned`) и один скелет на врага, лимит `MAX_ALIVE` = 160, скелет анимируется только ближе 55 юнитов (`ANIM_DIST`). Клон стоит пару миллисекунд (распознавание рига) — толпа выпускается по `SPAWNS_PER_FRAME` = 2 за кадр из очереди `pendingSpawns`. Тени от врагов — `ENEMY_SHADOWS` в `game.ts` (второй скиннованный проход на каждого; на слабом GPU выключить первым делом). Логика 40 врагов с анимацией — 1.2 мс/кадр.
- **Золото — инстансы** одного октаэдра: один draw call на все монеты.
- **Тени**: карта 1024², квадрат 64 юнита вокруг игрока (16 px/юнит).
- **Чанки строятся по одному за кадр** в порядке удалённости (`BUILDS_PER_FRAME` в `chunks.ts`): переход границы чанка даёт 5 новых по ~0.7 мс — раньше это был рывок в одном кадре. При старте — всё сразу.

Замер логики на 150 врагах (только CPU, dt = 1/60): было 32 мс на кадр, стало 4.4 мс, из них 1.5 мс — `scene.pick` для прицела, по 0.5 мс — flow field, расталкивание и движение всей толпы.

Дальше, если понадобится: воркер для генерации чанков (сейчас не окупается — 0.7 мс на чанк), `scene.pick` только по ближним чанкам, отключение bloom на слабых GPU.

## Что подкрутить

Все параметры собраны в константы в начале файлов:

- `game.ts` — длительность этапа, размер толпы, частота спавна, лимит врагов, параметры штурма, статы и золото врагов, тени врагов.
- `enemy.ts` — масштаб врагов, дистанция и высота удара, замах, окружение (`SURROUND_DIST`, `FAN_ANGLE`), разброс скорости и сноса.
- `gold.ts` — радиус притяжения, время жизни монет.
- `weapons.ts` — веса выпадения и цены оружий (`WEAPONS`), темп и радиус летающего пистолета, число и урон дронов Роя, шанс/прыжки/дальность молнии, радиус, тик и шанс промаха Radiance и Ядра.
- `autoWeapons.ts` — кулдаун, дальность и урон бумеранга; число, радиус и скорость клинков; период, дальность, радиус взрыва и урон мортиры; время, тик и урон ионного поля.
- `shopItems.ts` — веса, цены и силы предметов (`RAGE_*`, `AEGIS_RECHARGE`, `VIAL_GOLD_MULT`, …); `recipes.ts` — ингредиенты, цены и силы рецептов; `game.ts` — `SPIN_BASE`/`SPIN_STEP` (цена вращения), `STOCK_ITEMS`, `COUPON_DISCOUNT`, `SECOND_WIND_HP`, `BULLET_BLAST_MULT`, цвета секторов, `BOSS_CHANCE`/`BOSS_COUNT`/`BOSS_SCALE`/`BOSS_HP_MULT`/`BOSS_DAMAGE_MULT` утешительного колеса; `wheel.ts` — время и число оборотов вращения, задержка автозапуска.
- `weapon.ts` — `GUN_PRESETS` (дробовик, автомат), `CRIT_MULT`; `projectiles.ts` — `PIERCE_FALLOFF`, `RICOCHET_RANGE`, замедление от пули.
- `terrain.ts` — амплитуда холмов, радиус блока стены, диапазон высот, число и длина цепочек стен.
- `terrainMesh.ts` — палитра земли (`PALETTE`), порог «скалы» по крутизне, джиттер цвета.
- `chunks.ts` — радиус загрузки чанков.
- `environment.ts` — небо, цвета и сила света, плотность тумана, bloom/экспозиция/виньетка.
- `player.ts` — разгон/торможение, сила и высота прыжка, гравитация взлёта/падения, coyote time и буфер, инерция в воздухе, амортизация приземления, скорость приседа.
- `humanoidRig.ts` — амплитуды анимации: шаг, присед, leap, наклон корпуса, дыхание, голова.
- `thirdPersonCamera.ts` — сглаживание вертикального следования камеры.
- `upgrades.ts` — список улучшений (оружейные меняют общие `weaponStats`).
- `weapon.ts` — разброс и нагрев пистолета; радиус, сектор, множитель урона и длительность взмаха меча. Базовые кулдауны: `HAND_GUN_COOLDOWN`, `SWORD_COOLDOWN` в `game.ts`, `DRONE_COOLDOWN` в `weapons.ts`.
- `characterModel.ts` — цвета процедурного персонажа (`PAL`), лимиты для GLB.
