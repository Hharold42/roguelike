# Roguelike

Top-down roguelike-survivor на [Babylon.js](https://www.babylonjs.com/) + TypeScript + Vite.
Бесконечная процедурная карта, волны врагов, улучшения между этапами.

## Запуск

Нужен [Node.js](https://nodejs.org/) 20+ (проверялось на 24).

```bash
npm install      # один раз, ставит зависимости
npm run dev      # dev-сервер с горячей перезагрузкой
```

Откройте адрес из консоли (обычно http://localhost:5173). Изменения в `src/` подхватываются без перезапуска.

Продакшен-сборка:

```bash
npm run build    # проверка типов + сборка в dist/
npm run preview  # локально посмотреть собранную версию
```

Содержимое `dist/` — статика, её можно выложить на любой хостинг.

## Управление

Камера от третьего лица, как в Genshin Impact: первый клик по полю захватывает курсор.

| Действие | Клавиши |
|---|---|
| Движение (относительно камеры) | `W A S D` / стрелки |
| Прыжок | `Пробел` |
| Присед (удерживать) | `Ctrl` / `C` |
| Камера | мышь (с захваченным курсором) |
| Дистанция камеры | колесо мыши |
| Стрельба по перекрестию | зажать ЛКМ |
| Отпустить курсор | `Esc` |
| Новый забег после смерти | `R` |

Оружие всегда наготове: корпус повёрнут на точку под перекрестием, рука с пистолетом наклоняется за ней вверх/вниз; движение вбок и назад — стрейф (назад ноги идут в обратную сторону). Камера не проваливается в склоны и подтягивается ближе, если между ней и персонажем стена. Параметры (чувствительность, пределы наклона и дистанции) — в `src/thirdPersonCamera.ts`.

Движение с инерцией: разгон до полной скорости ≈ 0.15 с, остановка ≈ 0.15 с; упёрлись в стену — скорость гаснет. Прыжок (`src/player.ts`):

- **переменная высота** — удерживать пробел ≈ 2.2 юнита, отпустить сразу ≈ 0.6;
- гравитация асимметричная (взлёт мягче, падение резче) с коротким «зависанием» в вершине;
- в воздухе инерция сохраняется: прыжок с разбега — leap на несколько юнитов, подруливание слабое, отпустили клавиши — скорость плавно гаснет;
- **coyote time** 0.1 с после схода с края и **буфер** 0.12 с до приземления — нажатие не теряется;
- приземление амортизируется (колени, наклон) и при жёстком падении режет разбег;
- камера по вертикали следует за персонажем с запаздыванием, чтобы прыжки не дёргали кадр.

Присед вдвое замедляет; модель садится по-настоящему — сгибом бёдер и коленей с опусканием таза (стопы остаются на земле), корпус наклоняется вперёд, коллайдер и точка обзора камеры опускаются. Прыжок из приседа выпрямляет.

Стены физические: сбоку блок не пройти, но на него можно запрыгнуть и ходить по верху (`Terrain.floorAt` — верх стены или рельеф под персонажем). Никакого «примагничивания»: чтобы оказаться на блоке, ступни в прыжке должны подняться выше его верха (прыжок ≈ 2.2, низкие блоки 1.8–2.2 берутся с земли), высокие — ступеньками с соседних блоков. Сошёл с края — падаешь. Враги по стенам не лазят и **не достают игрока на блоке**: удар проходит, только если ступни игрока не выше ступней врага на `ATTACK_HEIGHT` (1.1). Толпа собирается у подножия (flow field стартует от свободных клеток вокруг блока).

## Враги

- Модель — та же, что у игрока (`/models/player.glb`), **в 3/4 роста** (`ENEMY_SCALE`) и перекрашенная: обычные — красные, к 9-му этапу — фиолетовые; элитные — в 1.35 раза крупнее (≈ рост игрока), тёмно-красные, светятся. Нет файла — процедурный человечек. Каждый враг — независимая копия шаблона со своим скелетом и ригом (`loadCharacterTemplate` → `instantiate`), меши склеены в один (`mergeSkinned`): один draw call на врага.
- **Толпа, а не колонна**: у каждого свой боковой снос вдоль маршрута (постоянный + качающийся), скорость ±20 %, а ближе 9 юнитов враг идёт не по прямой, а со своего угла — вместе с расталкиванием получается кольцо вокруг игрока. Проверка на 40 врагах из узкого сектора: через 9 с заняты все 8 секторов вокруг игрока.
- **Удар с замахом**: 0.32 с от начала выпада до урона, урон проходит только если в этот момент игрок всё ещё в зоне — отбежать или отпрыгнуть можно. Модель делает выпад вперёд.
- Статы (`game.ts`): HP 3 + 1.5/этап (элита ×6), скорость 4.2 + 0.3/этап, урон 8 + 2/этап. Толпа в начале этапа 10 + 4/этап, штурм ×4.
- **Золото** (`gold.ts`): с врага падает 2 + этап/2 (элита 12 + 2·этап) монетами (до 5 штук), они подпрыгивают, ложатся на землю и в радиусе 4.5 юнита летят к игроку. Лежат монеты 25 с. Шкала в HUD ведёт к следующему улучшению оружия.

## Оружие (`weapon.ts`)

Любой стреляющий предмет — экземпляр `Weapon`: свой базовый кулдаун и нагрев ствола, общий пул пуль (`ProjectilePool` только двигает пули и считает попадания). Характеристики у всех оружий **общие** — `WeaponStats` в `player.weaponStats` (урон, пуль за выстрел, множитель кулдауна). Улучшения между этапами меняют именно этот объект, а не конкретный пистолет, поэтому «Тяжёлые снаряды», «Мультивыстрел» и «Скорострельность» действуют и на пистолет в руке, и на летающий, и на оружие, купленное позже. Сейчас два оружия: ручной пистолет (`handGun` в `game.ts`, кулдаун 0.22) и летающий (в `weapons.ts`, кулдаун 0.5, без нагрева).

## Улучшения за золото (`weapons.ts`)

Покупаются по порядку клавишей **B**, когда золота хватает (подсказка под шкалой):

1. **Летающий пистолет** — 100. Парит слева над плечом, сам разворачивается на ближайшего врага в радиусе 28 и стреляет 2 раза в секунду (быстрее с бафами скорострельности, веером при мультивыстреле, с уроном из общих stats). Ствол не греется — разброс минимальный. Пули те же, что у игрока — попадают в стены, приносят золото и запускают молнию.
2. **Молния** — 500. Любое попадание пули (игрока или пистолета) с шансом 30 % бьёт ещё по двум ближайшим врагам в 8 юнитах от поражённого, урон — как у пули. Молния молнию не запускает. Визуал — ломаная `LinesMesh`, гаснет за 0.18 с.
3. **Radiance** — 1000. Кольцо радиусом 6 вокруг игрока: враги внутри каждые 0.5 с получают половину урона игрока (минимум 1), а их удары с шансом 30 % наносят 10 % урона (`WeaponSystem.incomingDamage`).

## Графика

`src/environment.ts` — всё окружение в одном месте:

- **небо** — процедурный `SkyMaterial` из `@babylonjs/materials`: солнце на небе стоит там, откуда светит `lightDir`, так что тени и блики согласованы с диском солнца. Мутность, голубизна, яркость — константы `SKY_*`;
- **свет** — тёплое солнце (`DirectionalLight`) плюс полусферический свет неба: голубоватый сверху, тёплый отражённый снизу;
- **тени** — PCF с `normalBias` (размытые экспоненциальные давали сплошное самозатенение на призмах стен), ортокадр 90×90 юнитов вокруг игрока, чтобы разрешение карты теней не размазывалось по всем загруженным чанкам. Стены — flat shading (`convertToFlatShadedMesh`), иначе шестигранник затеняется как цилиндр;
- **дымка** — экспоненциальный туман в цвет горизонта; плотность подобрана так, чтобы край загруженных чанков (~70 юнитов) тонул в ней;
- **постобработка** — `DefaultRenderingPipeline`: FXAA, bloom только на ярких эмиссивах (трассеры, ствол, элитные враги), тонмаппинг ACES, лёгкая виньетка. Если нужна производительность — отключите вызов `setupPostFx` в `game.ts` или уберите bloom.

### Стрельба

Пуля — маленький быстрый трассер (260 юнитов/с, дальность 120). Вылетает из среза ствола и летит по прямой в точку, которая была под перекрестием в момент выстрела (враг, земля или, если там небо, далёкая точка по направлению камеры). Столкновения проверяются по всему отрезку пути за кадр, поэтому пуля не проскакивает врагов и стены на любом FPS.

Разброс: с некоторым шансом пуля отклоняется на 1–2° в случайную сторону. Шанс — 2 % у «холодного» ствола и растёт с каждым выстрелом подряд до 30 % (примерно 12 выстрелов). После окончания очереди шанс возвращается к 2 % за 0,5 с (после пары выстрелов) … 2 с (после максимального нагрева). Перекрестие расходится с нагревом ручного пистолета. Константы разброса — в начале `src/weapon.ts`, полёта пули — `src/projectiles.ts`.

## Правила

- Этап длится 30 секунд. По истечении игра ставится на паузу и предлагает одно из трёх улучшений; после выбора игра продолжается с того же места.
- Враги появляются постоянно за краем экрана; с каждым этапом новые враги сильнее и приходят чаще. В начале этапа приходит толпа.
- Каждый 10-й этап — штурм: толпа в 4 раза больше, каждый 10-й в ней элитный (крепче, крупнее, светится красным).
- Отставшие враги телепортируются ближе к игроку — от толпы не убежать.

## Своя модель персонажа

Положите файл в `public/models/player.glb` — игра подхватит его автоматически. Пока файл грузится, показывается процедурный персонаж из примитивов.

### Страница просмотра — `/viewer`

Отдельная страница (ссылка в правом нижнем углу игры или http://localhost:5173/viewer): модель загружается тем же кодом, что и в игре, но её можно рассмотреть.

- ЛКМ — вращать камеру, колесо — зум, ПКМ — сдвиг; стрелка на полу показывает, куда персонаж считается смотрящим;
- **Ходьба** (или зажать пробел) — анимация шага; **Присед** (или зажать `C`); **Прыжок** (или `J`) — мини-физика с теми же числами, что у игрока: видно leap с разбега, прыжок с места и приземление; **Вращать** — подставка крутится; **Скелет** — кости линиями; **Каркас** — wireframe;
- **Разворот** — подкрутить угол, чтобы понять, какой `yaw` нужен модели без скелета;
- панель показывает треугольники, меши, кости, найденные анимации и результат распознавания рига;
- **Открыть GLB…** или перетащить файл в окно — посмотреть любую модель, не копируя её в `public/models`. Так удобно проверять модель перед тем, как сделать её игровой.

Что делает загрузчик (`src/characterModel.ts`):

- приводит рост к 2 юнитам, ставит ноги на землю, центрирует;
- **упрощает** меши до бюджета 6 000 треугольников (`triangleBudget`). Меши со скелетом не упрощаются — упрощение теряет веса костей;
- модели тяжелее 150 000 треугольников (`triangleHardLimit`) отклоняются с предупреждением в консоли браузера (F12), остаётся процедурный персонаж;
- анимации из файла: группы с именами `walk/run/move` и `idle/stand` переключаются при движении; иначе зацикливается первая настоящая анимация (группы из одного кадра — это поза, они игнорируются);
- **скелет без анимаций** (типично для моделей со Sketchfab, MMD, Mixamo без клипов): `src/humanoidRig.ts` распознаёт гуманоидный риг по геометрии — имена костей не важны, нужны только суффиксы стороны (`.L/.R`, `Left/Right`). Находятся бёдра, колени, плечи, локти и кисти, а по ним — таз (общий предок бёдер), грудь (общий предок плеч), позвоночник между ними и голова;
- **поза**: T-поза или A-поза не остаётся как есть — левая рука опускается вдоль тела, правая вытягивается вперёд, в кисть ставится пистолет-заглушка из примитивов (замените на модель оружия в `attachPlaceholderGun`, `src/characterModel.ts`);
- **анимация** идёт от состояния движения (`src/motion.ts`: скорость, стрейф, полёт, приземление, присед), а не от нажатых клавиш:
  - ходьба — ноги шагают со сгибом колена, левая рука машет противофазно со сгибом локтя, правая держит прицел и лишь покачивается, корпус наклоняется по скорости и покачивается в такт, кренится в сторону стрейфа;
  - покой — дыхание грудью, перенос веса, голова медленно оглядывается и держит горизонт при наклонах корпуса, чуть повторяет наклон прицела;
  - присед — бедро вперёд на θ, колено назад на 2θ, таз опускается на длину ноги × (1 − cos θ): стопы остаются на месте;
  - прыжок с места — ноги поджаты, к земле распрямляются; **leap** с разбега — ведущая нога вперёд, задняя назад, свободная рука вверх; приземление — амортизация коленями;
  - наклон корпуса компенсируется в оружейной руке, так что ствол не уезжает с прицела;
- **разворот**: если риг распознан, направление «вперёд» берётся по стопам — по костям носков, а если их нет, по вершинам меша ступни (она выступает вперёд от лодыжки). Модель сама поворачивается лицом по камере. Если скелета нет — используется параметр `yaw` (по умолчанию 180°; если персонаж смотрит спиной, поставьте `0`).

Что пишет консоль при загрузке: `[rig] бёдра N, колени N, руки N, позвоночник N, голова, оружейная рука найдена` и угол разворота. Если рук/ног 0 — риг нестандартный, останется поза покоя.

Большие файлы (десятки мегабайт) грузятся долго и раздувают `dist/` — перед использованием лучше сжать модель, например через [gltf-transform](https://gltf-transform.dev/) (`gltf-transform optimize in.glb out.glb`) или Blender (Decimate).

## Производительность

Что сделано, чтобы толпа держала 60 FPS, и что помнить при доработках:

- **Никакого `moveWithCollisions` у врагов.** Движок коллизий Babylon проверяет движущийся меш против *всех* коллайдеров сцены; при 150 врагах и ~220 стенах это съедало 30 мс на кадр. Враги ходят по hex-клеткам: `terrain.isWallAt(x, z)` — O(1), при упоре скользят вдоль стены (`Enemy.update`). Игрок остался на `moveWithCollisions` — один вызов в кадр, коллайдеры — только стены.
- **Расталкивание толпы** — `CrowdSeparator`: пространственная сетка с ячейкой 0.8, соседей ищем в 3×3 ячейках. Было O(N²) пар × коллайдеры, стало O(N). Игрок — твёрдый круг, врагов из него выталкивает.
- **Враги — скиннованные клоны одной модели**, поэтому толпа больше не бесплатна: один меш (склейка `mergeSkinned`) и один скелет на врага, лимит `MAX_ALIVE` = 160, скелет анимируется только ближе 55 юнитов (`ANIM_DIST`). Клон стоит пару миллисекунд (распознавание рига) — толпа выпускается по `SPAWNS_PER_FRAME` = 2 за кадр из очереди `pendingSpawns`. Тени от врагов — `ENEMY_SHADOWS` в `game.ts` (второй скиннованный проход на каждого; на слабом GPU выключить первым делом). Логика 40 врагов с анимацией — 1.2 мс/кадр.
- **Золото — инстансы** одного октаэдра: один draw call на все монеты.
- **Тени**: карта 1024², квадрат 64 юнита вокруг игрока (16 px/юнит).
- **Чанки строятся по одному за кадр** в порядке удалённости (`BUILDS_PER_FRAME` в `chunks.ts`): переход границы чанка даёт 5 новых по ~0.7 мс — раньше это был рывок в одном кадре. При старте — всё сразу.

Замер логики на 150 врагах (только CPU, dt = 1/60): было 32 мс на кадр, стало 4.4 мс, из них 1.5 мс — `scene.pick` для прицела, по 0.5 мс — flow field, расталкивание и движение всей толпы.

Дальше, если понадобится: воркер для генерации чанков (сейчас не окупается — 0.7 мс на чанк), `scene.pick` только по ближним чанкам, отключение bloom на слабых GPU.

## Что подкрутить

Все параметры собраны в константы в начале файлов:

- `game.ts` — длительность этапа, размер толпы, частота спавна, лимит врагов, параметры штурма, статы и золото врагов, тени врагов.
- `enemy.ts` — масштаб врагов, дистанция и высота удара, замах, окружение (`SURROUND_DIST`, `FAN_ANGLE`), разброс скорости и сноса.
- `gold.ts` — радиус притяжения, время жизни монет.
- `weapons.ts` — цены (`WEAPON_TIERS`), темп и радиус летающего пистолета, шанс/прыжки/дальность молнии, радиус, тик и шанс промаха Radiance.
- `terrain.ts` — амплитуда холмов, радиус блока стены, диапазон высот, число и длина цепочек стен.
- `terrainMesh.ts` — палитра земли (`PALETTE`), порог «скалы» по крутизне, джиттер цвета.
- `chunks.ts` — радиус загрузки чанков.
- `environment.ts` — небо, цвета и сила света, плотность тумана, bloom/экспозиция/виньетка.
- `player.ts` — разгон/торможение, сила и высота прыжка, гравитация взлёта/падения, coyote time и буфер, инерция в воздухе, амортизация приземления, скорость приседа.
- `humanoidRig.ts` — амплитуды анимации: шаг, присед, leap, наклон корпуса, дыхание, голова.
- `thirdPersonCamera.ts` — сглаживание вертикального следования камеры.
- `upgrades.ts` — список улучшений (оружейные меняют общие `weaponStats`).
- `weapon.ts` — разброс и нагрев; базовые кулдауны: `HAND_GUN_COOLDOWN` в `game.ts`, `DRONE_COOLDOWN` в `weapons.ts`.
- `characterModel.ts` — цвета процедурного персонажа (`PAL`), лимиты для GLB.
